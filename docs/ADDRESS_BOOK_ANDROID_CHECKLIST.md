# P1 address book: physical Android verification

**Not executed by the agent.** Record device/OEM, Android version, feature-branch commit, APK build/profile and pass/fail notes. Use synthetic recipients/phone numbers. Do not publish recordings containing personal addresses or GPS coordinates. Repeat the [P0 permission checklist](ANDROID_CHECKLIST.md) on the same build.

1. **Entry points:** open the selector through Home and Cart, including an empty cart. Back should return to the originating screen. Search, product shelves, quantities, coupons and bill calculations must remain intact.
2. **Manual with no GPS:** deny foreground location, then block it through Android Settings. Add an address manually in each state, with GPS services off and airplane mode on. Use Current Location must be unavailable; the form must remain usable and make no location/Contacts request. Save and select should work.
3. **Validation:** try blank required fields, PINs with fewer/more than six digits or a leading zero, an invalid optional phone, incomplete coordinates and out-of-range coordinates. Check readable errors and accessible field labels. Empty optional phone/coordinates must work. Confirm PIN format acceptance does not claim serviceability.
4. **Labels and recipients:** save Home, Work, Dad's Home, Mom's Place, Friend and a custom label. Give a label a different recipient relationship; it must not be inferred or changed automatically. Add/edit recipient name and phone manually. No Contacts prompt should appear.
5. **Address details:** enter flat/house, tower/block, society, landmark, city/state/PIN and multiline instructions. Edit and reopen; verify exact fields survive, including an other-society-app name. A saved address must keep its stable ID through editing.
6. **Gate preferences:** exercise no restriction, MyGate, NoBrokerHood, other app and call recipient at gate. Combine Door/Gate with Call Before Arrival. Check that the UI describes demo instructions only and never claims approval, launches a society app or calls a recipient.
7. **Default versus selection:** first save should be default and selected. Add a second address; it should become selected while the first remains default. Set a third default without changing the current delivery selection. Restart and verify both indicators and Home/Cart summaries.
8. **Delete:** cancel and confirm deletion. Delete a nonselected address, the selected address, the default, and the last address. Confirm deterministic fallback indicators or the empty state. Force-close/restart; removed address text must not return.
9. **Current Location:** grant foreground access through the existing permission flow or Settings, return, and wait until ready. Tap Use Current Location once and rapidly twice. Expect one guarded request and editable coordinates, without an automatically saved address. Fill the remaining fields and explicitly Save.
10. **GPS failure/stale results:** turn GPS off and request a suggestion; check the fallback and continued manual entry. With a slow fix, type new fields, navigate Back, or revoke access in Settings before the result arrives. Late coordinates must not overwrite edits or reappear after leaving. Retry after a timeout; an unfinished native request must not overlap a replacement call.
11. **Permission independence:** with saved manual/GPS-assisted addresses, revoke location and notifications, then background/resume, reopen the book and restart. The address book, default and current selection must be retained. P0 live-coordinate display must still clear on revocation.
12. **Keyboard and Back:** on a small phone and enlarged fonts/TalkBack, tab through every input, type continuously, focus the final instructions field and keep Save reachable. There must be no focus loss/remount or double keyboard resize. First Android Back may dismiss the keyboard; navigation Back must offer Keep Editing/Discard for an unsaved draft. A successful Save must return without a discard prompt. Failed Save must retain the draft.
13. **Storage recovery (debug fixture only):** seed malformed JSON, a mix of valid/invalid records, duplicate IDs and missing selected/default IDs under `plazza.addresses.v1`. Valid records should survive with a visible review warning and confirmation action. Test an unsupported version and simulated read/write failures; neither may silently overwrite saved data. Retry should recover without touching shopping storage. Automated repository tests cover these cases without real personal data.
14. **Future snapshots/mock checkout:** verify existing mock Place Order still behaves as before and writes no standalone address snapshot. There is no receipt/history UI in this phase. The tested snapshot API is reserved for the future atomic order-plus-snapshot write before cart clearing.
